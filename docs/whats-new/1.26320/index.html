Help / What's New

1.26320 — 16 November 2026

On a Windows or Linux PC with a graphics card, local models that don't fit on the card read long prompts faster, and on Windows models load faster too. You don't need to change a setting. On a Mac, an update now finishes by restarting into the new version. Documents keep the View menu choices you make, everywhere you open them, and several toolbars are rebuilt so each reads as one row.

Faster local models on PCs with a graphics card

When a model is too big for your graphics card, part of it stays in your computer's ordinary memory, and the card copies that part across while it reads a long prompt. That part used to be read from the model file only as needed, which the card can copy only slowly. Gezel now reads it into memory the card can copy from directly.

In our measurements on an AMD Radeon card, long prompts were read between a third faster and four and a half times faster, depending on the model. Qwen 3.8 Flash Next read them 2.6 times faster. Replies are written at the same speed as before.

Memory used this way can't be moved out to disk when the computer runs short, so Gezel does this only when it knows exactly how much the model needs and that much memory is free, with 4 GB to spare. Otherwise the model loads as before. If a model fails to start this way, Gezel starts it the old way.

On Windows, models are also read from disk a faster way. A 17 GB model that fits on the card loaded in 3.6 seconds instead of 8 to 11, and Qwen 3.8 Flash Next loaded in 16 seconds instead of 26.

This applies to the llama.cpp engine on a Windows or Linux PC whenever it runs on the graphics card, whether NVIDIA, AMD, or another card through Vulkan. Macs are unchanged. It happens when Model loading in Settings → This PC (llama) is on Auto, the default. A loading mode you chose there yourself still applies.

Mac updates finish by themselves

On a Mac, an update installs through the macOS installer. Gezel used to hand the package over and hear nothing back: the installer replaced the app and restarted its background service while the window still said "Opening installer…".

Now Gezel watches for the installer to finish its last step, then restarts into the new version on its own. While the installer is open, Home and Settings → About say that Gezel is installing, with a Show installer button in case its window went behind another one. Gezel doesn't check for other updates while one is installing. If the app was updated some other way, such as a package you opened yourself, Gezel says the new version is installed and offers Restart Gezel. Your crew, projects and chats are not affected either way.

The version you update from runs the installer, so you'll see this starting with the update after this one.

Documents keep your View menu choices

A file now opens with its outline hidden. Turn the outline on from the View menu and it stays on wherever you read your files: a project's files and Artifacts drawer, the Documents library, a document opened from outside Gezel, and a file a chat links to. Documents you already have open change too. The rest of the View menu (previews, the status bar, block tags, theme styling) and the Document or Block choice are remembered the same way, and they hold after a restart. Small editors, such as the message box and note fields, keep their own layout.

Toolbars that read as one row

Several toolbars had grown into rows of small boxes at different heights. They now follow one pattern:

  • The message box. The attach buttons and Send now sit in a row under what you write, so you write first and send from below, and Tab moves in that order. The box's border turns copper while you are typing in it. In the terminal, Fire sits in the same place under the command.

  • File panes. The title names the place: Artifacts drawer, or the folder's own name, with its full path when you point at it. New folder, New file and the fold arrow are quiet buttons beside the title. The view modes, show hidden files and the button that opens the folder in your file manager share one strip under it. When the pane is folded to its narrow rail, New file and the file-manager button stay at the bottom.

  • Tasks. One group holds everything that decides which tasks are listed: One-time, Scheduled and Night Shift, then the project, status and assignee pickers, which turn the accent color while they narrow the list. New task stands alone at the end. On a task, the status buttons and the assignee share one group, and the filled button (Start task, or Try again on a paused task) always comes last. Discard on a draft no longer looks like a second Start button.

  • Activity. Each question and each night's review is now its own card, so a stack of night reports no longer reads as one long document.

Smaller things

  • Gemma 4 26B is now split correctly between a smaller graphics card and system memory. Gezel had miscounted about 8 GB of the model as being on the card, so its plan for where each part goes was wrong.

  • A media review whose check requires looking at the picture keeps the tool to look at it when the step is tried again. Without it, a reviewer refused to finish until the task paused.

  • When a step is finished twice in quick succession, with a file saved again in between, the second attempt is now judged on its own. It used to get the first attempt's verdict, such as a file "not found", and the step sat idle until the task paused.

  • With the Codex provider, time spent reconnecting after a dropped connection no longer counts against a turn's time limit, up to a bound. A turn that runs out of time while reconnecting is no longer reported as rate limited.

  • The seconds counter beside a reply that is still being written now shows only in debug mode. The notice that appears when a reply stalls still shows for everyone.

  • Home no longer shows a separate "ready for you" count. The Activity button in the title bar already counts finished work.

  • In Projects, the navigation rail folds to its icons while the project list is open, so only one list of projects shows at a time. Fold the project list and the rail comes back.

  • The description field in New task no longer shows Write and Source tabs. Its formatting buttons stay.

  • The AI button in the document editor now uses the same sparkles as DocBlocks.

  • Document editor updated (Squisq 2.13.17), and diagrams (Mermaid 11.17.2).

For developers

  • The container image is built from the npm release run's final commit instead of the CLI's tag, so it carries every package's version bump. The build stops if core's version at that commit differs from the one the published CLI depends on. See docs/container.md in the repository.

  • @bendyline/gezel-capacitor's bundled catalog now matches the pinned catalog content (gilde 0.3.10), where it had been left on 0.1.80. It now carries the docbench scores described for 1.26317, and adds LFM3 1.7B.

  • Hono updated to 4.13.16.

Things to see and do after update

  • If you run local models on a Windows or Linux PC with a graphics card, check that Model loading under Settings → This PC (llama) is on Auto.

  • Open a document and turn on the outline from its View menu. It stays on everywhere you read your files.
