Help / What's New

1.26326 — 22 November 2026

A project can now follow web pages and keep its own copies of them, and a web address you write in a message is saved and handed to the gezel with your words. Pages a gezel builds can now use three.js, Chart.js, React and other popular libraries with no internet connection, and you can export a page to share it. Connecting a calendar, OneDrive or SharePoint no longer needs a developer app of your own, and connections now show plainly when you're offline instead of failing. Claude Code, Codex and Copilot gezels now run commands through Gezel's own tools unless your security level is Unrestricted.

Follow web pages from a project

A gezel that needed something from the web used to browse for it while it worked, or do without. A project can now follow web pages instead: a product's documentation, a supplier's price list, a team wiki. Gezel visits each page in a browser of its own, keeps its text and a few screenshots, and checks again on a schedule. Gezels read those copies and never browse while they work, so a page can't send them anywhere.

Open the project's Connections tab, choose Add connection, then Websites, and paste one or more addresses. You choose how far to follow links, how many pages to keep and how often to check for changes. Gezel visits at most one page every second or two and follows each site's rules for crawlers.

The project's Web pages view tab lists the saved pages by site. Each row leads with what you'd want to know, such as "Changed 2 days ago" or why a page couldn't be saved. Reading shows a page's text and Screenshots shows how it looked. Each site also gets an overview of its pages and a monthly change log, both of which gezels read.

For a site you sign in to, press Sign in… on its connection and sign in in the window Gezel opens. The sign-in is kept for that connection only, encrypted on your computer, and Gezel never sees your password. If the site signs you out later, Gezel stops refreshing it and keeps everything it saved.

Lookouts can watch a site too. In Connections → Lookouts, choose the site, then a page that changed, a new page, or words that appear (such as "sold out"), and what should happen next.

Gezel never clicks, types or fills in anything on a page, never downloads files from one, and never replaces a good copy with a bot check or a sign-in form. Saved web pages covers the rest.

Links in a message are saved and included

Asking "Can you summarize https://example.com/pricing?" used to depend on whether the gezel could reach the web at all. Now, when you write a web address that starts with https:// or www., a line above the message box says the page will be saved here and included in the chat. When you send, Gezel saves the page first and gives it to the gezel along with your message.

Press × on that line if you don't want the page fetched, or Save now to save it while you're still writing. Under your sent message, a row with the page's title opens the saved copy, and a page that couldn't be saved shows the reason. Only your own messages do this. An address in a gezel's message, an app's request or a scheduled nudge is never fetched this way.

Pages can use popular libraries, with no internet

A page a gezel builds runs in a preview with no network below Unrestricted, so a 3D scene, a chart or a React interface had to be written from scratch, and a page that loaded a library from the web simply broke. Gezel now keeps popular libraries on your computer and hands them to the page from there: three.js for 3D, Chart.js and D3 for charts, and React, Preact and Vue for interfaces. The page names the library the ordinary way, by its package or its usual web address. Export the page and the library goes with it, so the copy opens anywhere.

A library downloads the first time a page uses it, at the exact version Gezel's catalog lists, and is checked before any page loads it. Automatic downloads happen only when your security level lets Gezel use the network. Settings → More settings → Page libraries lists what's on this computer, downloads one ahead of time, removes one, or turns automatic downloads off. The Mac App Store and Microsoft Store versions come with a fixed set and never download.

Gezels are told which libraries are on hand and stay with plain JavaScript unless one clearly helps. The chart and dashboard craftbooks can now draw with Chart.js instead of plotting axes by hand, and the game and app craftbooks may use a library where it fits.

React pages written for Babel's in-browser compiler now run without downloading it, because Gezel compiles the page's JSX itself. React 19 is included, and a component file that uses JSX without importing React works as it does in a Vite project.

To share a page, press the download arrow above it in the project's output pane, beside the button that opens it in your browser. One file (.html) puts the libraries, styles and images inside a single file that opens by double-clicking and can be emailed. Folder (.zip) keeps the files side by side, ready for a website. Either way, the libraries' license notices go with the copy.

Connections that are easier to set up and keep

  • No developer app for calendars and Microsoft files. Connecting a Google or Microsoft calendar, OneDrive or SharePoint used to mean registering a developer app with Google or Microsoft first. In the desktop app these now connect through Gezel's own sign-in apps, both named "Gezel (read-only)", which can only read. The connect form shows which app it will use. Mail, Google Drive and services such as X and LinkedIn still need an app of your own. If you have saved one, it is still used, and Use Gezel's app switches back. Your saved app also serves mail and Drive, so Gezel first names the kinds of connection that would need it added again; connections you already have keep working.

  • The right account. Google and Microsoft sign you in to whichever account your browser is already using, so a connection meant for one mailbox could end up copying another. Gezel now asks for the account named on the connection, checks which account actually signed in, and refuses the connection if they differ. The connection's row then reads "Signed in as …".

  • A clearer Add connection. It is now a two-step dialog that groups services by kind (mail, calendars, files, code, social, the web), each with its own mark, and opens the setup form on its own page.

  • Counts you can see. Each connection shows how many records it holds ("1,204 emails"), counting up while it syncs. Open shows its folder in the Artifacts tab.

  • Offline isn't an error. On a plane or with the cable unplugged, every connection used to fail at once in red. Now a connection that can't reach its service reads "Offline since 10:45 AM" in gray, and a line above the list says everything already downloaded is still here. Connections catch up on their own within seconds of the network coming back.

  • Removing can delete what was downloaded. Remove now offers Also delete what it downloaded, with how much that is. The box starts unchecked, because for a feed or a social account the copy may be the only one left.

  • Read-only connections refresh at the default level. Connections that only read, such as websites, feeds and wikis, now refresh on their own at Lockdown, as long as Gezel may use the network for you. Connections that can send or post still refresh on their own only where external services are allowed.

  • Email arrives more completely. A reply written below or between the quoted lines is kept, a forwarded message is kept whole, and mail that arrived during a long outage is no longer skipped when the connection catches up. An IMAP connection that drops partway through reconnects.

Tighter limits on what agents can run

Two of these change what you might notice: Claude Code and Codex gezels at the default level now work through Gezel's tools, and a send you didn't start waits in the outbox for your approval.

  • Claude Code, Codex and Copilot keep to Gezel's tools below Unrestricted. These agents bring a shell of their own that runs as your account, so it could read anything you can, including Gezel's own connection details. Below Unrestricted, Gezel now turns that shell off, keeps Copilot's sandbox on, and runs Claude's bypass mode and Codex's Full mode as Edit. Those gezels run commands through Gezel's own tools instead. At every level, the settings files those agents read no longer hold a live Gezel credential, and Claude Code's file tools can't open the files that do.

  • Unattended sends wait for you. A connection that can send or post now sends only when you press Approve or the gezel is working on a turn you started. A scheduled task by day, the night shift, a nudge or another gezel's request puts the message in the outbox for you to approve. Before, only the night shift waited.

  • Previews stay in their pane. A page a gezel made can no longer replace the app's own window, even if you open a link to it from a chat.

  • Git no longer runs a repository's hooks for gezels. A repository's settings can name programs for git to run: hooks, a file monitor, diff helpers. Gezel now turns them off whenever a gezel uses git or Gezel runs it on its own. A commit, merge or push you start still runs the repository's hooks, so Git LFS uploads and pre-commit checks work as before. A gezel's file tools never change anything inside a .git folder, under any spelling of the name, and when a gezel's script changes git's settings or hooks, Gezel puts them back. If a gezel's script makes a new repository, Gezel renames its .git folder to .git.gezel-set-aside so git doesn't read it, and you can rename it back.

  • Clones at Lockdown come from public code hosts. At Lockdown, a gezel can still clone from GitHub, GitLab, Bitbucket, Codeberg, Gitea or SourceHut over https. Any other host needs web services on.

  • Agent CLIs stay yours. Other apps that use Gezel's OpenAI-compatible or Ollama endpoints can no longer reach a Claude Code or Codex gezel, and a paired device can use only this computer's on-device models, not your cloud accounts.

  • Machine-wide projects can't reach your files. A project that every account on the computer shares can no longer point your Gezel at your folders, saved sign-ins or connections, and nothing starts there without someone starting it.

  • Terminal runs trust only catalog craftbooks. gezel do used to trust the scripts in any craftbook it started. A craftbook from your own folder or a project's, which gezels can edit, now needs --trust-scripts.

  • A crafted data query can no longer run a command, a script can no longer write outside its folder through a link, and a crafted email can no longer stall Gezel for an hour. IMAP mail connections now insist on encryption.

Smaller things

  • Activity now lists Needs you, then Working, Next and Ready, so work about to start sits right under the work running now.

  • The engine status in the title bar reads "Working" instead of "Generating", and "3 working" when several chats share the engine.

  • A step waiting for parts it sent out now reads "working through it in parts (0 of 15 done)" instead of naming a job it hasn't started. In a project where one gezel works alone, a task handed to a specialist is shown under that specialist's name.

  • The Say hello button on crew cards in a thread is gone.

  • The Artifacts tab now shows on every project, since it is where finished work lands. An app with nothing to keep there can still turn it off.

  • A step sent back by its check is retried with a shorter thinking budget, so the fix starts sooner.

  • Pull Request Review shows each patch line with its line number, a rejected finding names the rule it broke and quotes the words, and lockfiles and third-party notices are summarized by a script instead of read line by line.

  • In a code project, fact checking no longer refuses line numbers or wording in quotation marks, and it stops asking for a file to be read again once every source has been read in full.

  • On the smallest local models, the Illustrator and video roles keep their generation tools.

  • New in the catalog: Spark-X2.6 4B, a small model for tool use, coding and multi-step tasks, on the llama.cpp engine (3.5 GB download). Reports and documents written on Gemma 4 E4B now get a second look before they reach you.

  • In the terminal, first-run setup no longer offers a 153 MB download of optional engines when chat already works. gezel native install still adds them.

  • In the phone app, Narrate's Pop out button is hidden, since the app can't open one.

  • On a phone, a gezel asked to browse now says plainly that it can't open web pages in the app, instead of pointing you to a desktop Settings screen.

  • A build step that doesn't include the page check no longer asks the gezel to run it.

  • Document editor updated (Squisq 2.14.0), and catalog content (Gilde 0.3.14).

For developers

  • New package: @bendyline/gezel-retrieval 1.0.0, a browser-safe retrieval index for documents an app owns, with SQLite FTS5 and optional vectors over node:sqlite or sqlite-wasm.

  • @bendyline/gezel-capacitor adds createMobileTextEmbedder() for app-owned text embeddings, and the app SDK and phone retrieval accept app-owned knowledge passages beside catalog results.

  • Spectral connectors now run Prismatic's published npm components, pinned by version and hash and downloaded when a connection is made (connectors:draft-spectral drafts a manifest). See docs/connectors.md and ADR 0033 in the repository.

  • Observation-corpus tables can declare a dedupeKey for sources that deliver rows again.

  • Page libraries come from a new catalog kind, page-library, which pins each library's npm release by hash. The logic that reads CDN addresses, builds import maps and exports pages is in @bendyline/gezel/pages, with zod as its only dependency, for other apps that let a model write pages. gezel page export <project> <path> <out> [--single] exports a page from the terminal. See docs/page-libraries.md and ADR 0034 in the repository.

  • The /v1 streaming route no longer warns about a client that disconnects after the final chunk.

  • Gezel's own builds no longer run onnxruntime-node's install script, so they never download its optional CUDA providers. An npm install of the service still runs it.

Things to see and do after update

  • Add a website to a project from Connections → Add connection → Websites, then open the project's Web pages view tab.

  • Ask for a page with a 3D scene or a chart, then press the download arrow above it in the output pane to export it. Settings → More settings → Page libraries shows what's on this computer.

  • If a Claude Code or Codex gezel needs its own shell, check your level in Settings → Security & compliance. Below Unrestricted, it now works through Gezel's tools.
