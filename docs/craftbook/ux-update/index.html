Implement a UX Change

Deliver a described UX change the disciplined way: capture the before state from the real markup, make the smallest coherent change at the real sites in the product's own conventions, and prove the after state with the existing behaviors still working — under an enforced independent review.

How it runs

#StepWho runs itWhat happens
1Understand and capture the before stateDeveloperRestate the change as the user experiences it, find the real surfaces, and quote the current markup and wiring.
2Implement the smallest coherent changeWeb DeveloperDeliver the request at the real sites, in the product's own conventions, keeping existing behaviors wired.
3Validate the changed flowDeveloperWalk the new experience and build a concrete before/after grounded in the real files.
4Evaluate the deliverableReviewerIndependently grade the observable deliverable and route it to finish, repair, or user escalation.
5Repair the deliverableWeb DeveloperFix only the concrete gaps from the latest independent review.
6FinishDeveloperAll deterministic and reviewer criteria passed.
7Escalate unresolved concernsDeveloperThe bounded repair loop ended without a defensible pass.

Say something like "make this ux change" or "move the button" or "improve this flow" or "update the ui" in chat to start it.
