SOP Library

Write down how the work gets done, and keep it current. A librarian files every procedure by area with an owner and a last-reviewed date, flags the ones going stale, and answers “how do I…” from your own written steps.

What’s inside

The crew

  • Librarian Crew leadThe index-keeper.
  • CopywriterWrites for humans.

Plans it follows

  • Team Handbook SectionWrite a clear, reference-grade section of a team/company handbook — a policy, process, or how-we-work doc that a new hire can read once and act on correctly.
  • Documentation RewriteRewrite confusing existing documentation into clear, scannable, task-oriented prose without losing any technical fact: it first audits the current doc to catalog every problem — buried steps, undefined jargon, missing prerequisites, broken structure — and locks a clarity checklist, then rewrites the doc to fix exactly those issues while preserving every accurate instruction.
  • Knowledge Base ArticleWrite a support knowledge-base article that lets a user solve their problem without contacting support: it first scopes the exact user problem, the search terms they would use, prerequisites, and the success outcome, then writes a task-oriented article with a clear title, a short overview, numbered steps with expected results, screenshots/placeholders where needed, and a troubleshooting section, then a review pass verifies accuracy and self-service completeness.

Actions the crew can take

  • Library statusWhat in the library is out of date (flagged for an update or past its review date, most urgent first) and what is due for review within 30 days, each with owner and last-reviewed date, plus every procedure by area.
  • Find procedureAnswer a 'how do I…' question from the library: returns the best-matching procedure's steps exactly as written, with its owner and last-reviewed date.
  • Save procedureWrite a procedure into the library: title, area, owner and the steps in markdown (numbered, one action each).
  • Mark reviewedRecord that someone checked a procedure and it is still right; it restarts the review clock.
  • Flag procedureFlag a procedure that no longer matches how the work is done, with what changed in the words the person used.
  • Retire procedureRetire a procedure the business no longer uses.
  • List proceduresEvery procedure by area with owner, status, file path and review dates.

Each action is a small script that changes the app’s files, checked by Gezel’s security settings before it runs.

Files it keeps

Plain files in the project folder you can open, back up, and read: sops/index.json.
